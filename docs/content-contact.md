# 聯絡表單文案與實作

`ContactSwitch` 元件用在兩個地方：**`/contact` 頁**與**首頁最下方**。
同一份元件，改一次兩處一起更新。

## 兩區塊切換（`ContactSwitch`）

一般訪客（藍 `--color-primary`）與 KYC（橘 `--color-orange`）並排，
點一邊就滑過去蓋住另一邊，收合側留一條可點的直式標籤。白色欄位反白其上。

兩塊都用**帶透明度的漸層**（0.97 → 0.78／0.80），底下是白色區塊，
所以透明等於「往白色淡」，透得越多字越難讀，數值是算過的。

### KYC 面板改成淺色，橘色只留在送出鈕

整面橘太重。KYC 面板改成 白 → `--color-tint` 的漸層配深色字（17.24:1），
與藍塊形成對照，也回到 CLAUDE.md 的藍白主軸。白色輸入框疊在淺底上
分不出邊界，補了一條 `--color-border`。

橘色縮到只出現在 KYC 的送出鈕上——面積小，又保留它作為重點色的角色。

> ⚠️ **送出鈕是橘底白字，2.60:1，未達一般字 4.5:1 也未達大字 3:1。**
> 這是指定的視覺選擇，不是疏漏。要讓白字合格又保住橘感，把底色壓深到
> `#a94e00`（5.56:1）即可，只需改 `.submitKyc` 一行。
> 各深度：`#e06a00` 3.37、`#c25a00` 4.42、`#a94e00` 5.56、`#8a3d00` 7.64。

焦點框從寫死的白色改成 `currentColor`，才能同時適用兩塊。

截圖實測合成後的對比（漸層加透明度算不出來，只能量像素）：

| 位置 | 底色 | 對比 | 門檻 |
| ---- | ---- | ---- | ---- |
| 藍 標題 | `#203c65` | 11.08:1 | 3.0 |
| 藍 標籤 | `#2e3f53` | 10.76:1 | 4.5 |
| 藍 說明 | `#274168` | 10.28:1 | 4.5 |
| 橘 標題 | `#ff8623` | 7.89:1 | 3.0 |
| 橘 標籤 | `#dd9861` | 7.94:1 | 4.5 |
| 橘 說明 | `#ee8f44` | 7.86:1 | 4.5 |

送出鈕是白底：藍塊 `#0f3661` 12.21:1、橘塊 `#8a3d00` 7.64:1。

> 量測陷阱：白字疊在深底上時，**最亮的像素就是字本身**。取「背景色」時
> 白字要取暗端、深色字要取亮端，取錯會得出 1.04:1 這種假數字。

### 高度跟著內容走

不設 `min-height`。一般訪客只有四個欄位，固定下限會讓它展開時底下空一大片。

> 踩過的坑：收合側原本只用 `visibility: hidden`，但**那會保留版面空間**——
> 七個欄位被擠進 5.5rem 的窄帶後高度暴增，整列反而比展開前還高
> （實測 836 → 1422）。收合側的 `.body` 要一併用
> `grid-template-rows: 0fr` 收掉高度，改完是 602。

送出鈕 `justify-self: center`。

### 滑動

520ms → **720ms**，曲線從 `cubic-bezier(0.32,0.72,0,1)` 換成
`cubic-bezier(0.65,0,0.35,1)`。原本的收尾太急，「滑到一半卡住」的感覺
是從那裡來的；新曲線兩端都平緩。手機的高度展開同步調成 560ms。

- **桌機（900 以上）**：左右並排各半，點擊後選中側撐到 `100% - 5.5rem`、
  另一側收成 `5.5rem` 的窄帶，標籤轉直式。動畫用 `flex-grow` / `flex-basis`。
- **手機（900 以下）**：上下堆疊，「蓋住另一邊」不成立，改成點開才展開
  （`grid-template-rows: 0fr → 1fr`）。不這樣做的話整頁會是兩份完整表單。

**兩個斷點都是預設收合**（2026-09-06 依指示改）。桌機原本有一條
「一律展開」的覆寫（`grid-template-rows: 1fr`），一進頁面兩張表單就攤開；
現在共用基礎規則，預設 `0fr`、`.open` 才長出來。
實測 1512 寬：初始整塊 123px，點開後 313px。

收合側的內容用 **`visibility: hidden`** 隱藏，不是只降 opacity——
隱藏的元素本來就不可聚焦，比用 JS 逐一改 `tabindex` 可靠，也不必在 JS 裡
再判斷一次斷點。切換延遲到動畫結束，才不會一點下去內容就消失。

## 欄位

| 區塊 | 欄位 |
| ---- | ---- |
| 一般訪客 | 姓名、電話、信箱、諮詢內容 |
| KYC | 公司行號、統一編號、姓名、職稱、信箱、電話、公司電話（選填） |

KYC 七個欄位在桌機展開時排成兩欄，單欄會拉得太長。

### 統一編號有做檢查碼驗證

逐位乘上權重 `[1,2,1,2,1,2,4,1]`，把每個乘積的十位與個位相加，
總和能被 5 整除即為有效；第 7 位是 7 時 `+1` 也算通過。

做這個不是為了嚴謹好看——統編打錯一碼表單照樣送得出去，
但收到的資料是廢的，而且**沒有後端可以事後補救**。
已用真實統編驗證（04595257、23638777 通過；12345678 擋下）。

## ⚠️ 送出目的地尚未接

GitHub Pages 沒有後端，表單資料沒有地方可以送。CLAUDE.md 要求實作前先確認
要走哪一種，所以目前 `handleSubmit` 只擋下事件、**不送任何資料出去**。

兩個選項各有代價：

- **`mailto:`** — 無第三方、無相依套件，資料只經過訪客自己的郵件軟體。
  但體驗差（會跳出郵件軟體）、無法驗證送出成功，且收件信箱會暴露給爬蟲。
- **Formspree 之類的第三方** — 體驗好、有送出確認。但**資料會經過並儲存在
  第三方**。KYC 收的是統編、姓名、職稱、電話這類身分資料，
  這需要隱私權政策配合，是商業決定不是技術決定。

## 聯絡資訊 `[待補]`

Email、電話、地址全部未定。一個寫錯的 email 比整頁空白還糟，絕不放假值。

## 欄位 id 必須加前綴

兩個表單都有 `name`／`email`／`phone`，不加前綴會產生重複的 `id`
（`f-name` 等），點 KYC 的「姓名」標籤會跳去聚焦左邊訪客的欄位。
`FieldRow` 收一個 `scope` 參數，id 變成 `visitor-name`／`kyc-name`。

首頁與 `/contact` 各只渲染一份，不會互相衝突。

## 疊在首頁影片背景上的對比

首頁的區塊是半透明疊在影片上，藍色面板本身也有透明度（0.97 → 0.78），
兩層要一起算。四種最壞情況（影片亮／暗 × 左側有無色調）：

| 背景 | 面板 0.97 | 面板 0.78 |
| ---- | --------- | --------- |
| 影片亮·左有色調 | 11.80 | 9.44 |
| 影片暗·左有色調 | 12.32 | 13.09 |
| 影片亮·右無色調 | 11.22 | **6.30** |
| 影片暗·右無色調 | 12.50 | 14.47 |

最差 6.30:1，通過一般字的 4.5。KYC 面板是白→tint 的**不透明**漸層，
不受影片影響。

截圖實測（1920）：藍塊 12.32／12.38／12.85、KYC 全部 19.05、
送出鈕 12.20，全數通過。

> 量測陷阱：收合側的 `visibility` 切換有 **720ms 延遲**（等動畫結束才切）。
> 太早量會看到「收合側還有 4 個可聚焦欄位」，等滿再量才是 0。

## 展開前的使用者說明書彈窗 `[待補內文]`

依指示：點「一般訪客」或「KYC 系統」時**先跳出使用者說明書，勾選同意才展開**。

> ⚠️ **說明書內文一個字都沒寫。** 這一段的性質是同意事項（蒐集目的、蒐集項目、
> 保存期限、聯絡窗口），寫錯的後果比版面難看嚴重得多。目前是四條 `[待補]`，
> **需要你提供正式文字**，見 `src/components/ConsentDialog.tsx`。

### 行為

| 動作 | 結果 |
| --- | --- |
| 點未同意的面板 | 跳彈窗，面板不展開（`aria-expanded` 維持 false） |
| 未勾選 | Continue 停用 |
| 勾選 → Continue | 記下同意、面板展開、彈窗關閉 |
| Cancel／Esc／點背景 | 彈窗關閉，面板不展開 |
| 再點已同意的面板 | 直接展開，不再問 |
| 收合已展開的面板 | 直接收，不問 |

兩個面板各自同意一次（各有各的說明書）。

**同意只存在記憶體，重新整理就重來**——沒有寫進 `localStorage`。同意紀錄要能
查證才有意義，而這是純前端的靜態站，存在使用者瀏覽器裡的紀錄對雙方都不算數。
真的需要留存同意紀錄時，得跟表單送出目的地一起處理。

### 用原生 `<dialog>`

`showModal()` 自帶焦點鎖定、Esc 關閉、關閉後把焦點還給觸發元素、背景 inert。
自己刻一層 div 只會少做其中幾樣。要自己補的有兩件：

- **背景捲動**：`showModal()` 不鎖頁面捲動，開啟時設 `body { overflow: hidden }`
- **`margin: auto`**：UA 預設值被 global reset 的 `* { margin: 0 }` 蓋掉，
  不寫的話彈窗會貼在左上角（實測過）

還有一個坑：**沒有 topic 時不能 `return null`**。那樣 React 會在 effect 呼叫
`close()` 之前就把 `<dialog>` 移除，原生的焦點歸還跟著失效——實測取消之後焦點
掉到 `body`。元素常駐、只切換內容之後，實測焦點正確回到觸發的那顆按鈕。

實測（1024 以下）：點一般訪客 → 彈窗開、焦點在彈窗內、Continue 停用；
勾選後 Continue 啟用、按下去面板展開；Cancel 後焦點回到按鈕、面板未展開、
`body` 的 overflow 已還原。Esc 是瀏覽器原生行為，合成事件測不到，未在此驗證。
