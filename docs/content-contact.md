# CONTACT 頁文案與實作

## 兩區塊切換（`ContactSwitch`）

一般訪客（藍 `--color-primary`）與 KYC（橘 `--color-orange`）並排，
點一邊就滑過去蓋住另一邊，收合側留一條可點的直式標籤。白色欄位反白其上。

兩塊都用**帶透明度的漸層**（0.97 → 0.78／0.80），底下是白色區塊，
所以透明等於「往白色淡」，透得越多字越難讀，數值是算過的。

### KYC 面板改成淺色，橘色只留在送出鈕

整面橘太重。KYC 面板改成 白 → `--color-tint` 的漸層配深色字（17.24:1），
與藍塊形成對照，也回到 CLAUDE.md 的藍白主軸。白色輸入框疊在淺底上
分不出邊界，補了一條 `--color-border`。

橘色縮到只出現在 KYC 的送出鈕上——面積小，又保留它作為重點色的角色。

> ⚠️ **送出鈕是橘底白字，2.60:1，未達一般字 4.5:1 也未達大字 3:1。**
> 這是指定的視覺選擇，不是疏漏。要讓白字合格又保住橘感，把底色壓深到
> `#a94e00`（5.56:1）即可，只需改 `.submitKyc` 一行。
> 各深度：`#e06a00` 3.37、`#c25a00` 4.42、`#a94e00` 5.56、`#8a3d00` 7.64。

焦點框從寫死的白色改成 `currentColor`，才能同時適用兩塊。

截圖實測合成後的對比（漸層加透明度算不出來，只能量像素）：

| 位置 | 底色 | 對比 | 門檻 |
| ---- | ---- | ---- | ---- |
| 藍 標題 | `#203c65` | 11.08:1 | 3.0 |
| 藍 標籤 | `#2e3f53` | 10.76:1 | 4.5 |
| 藍 說明 | `#274168` | 10.28:1 | 4.5 |
| 橘 標題 | `#ff8623` | 7.89:1 | 3.0 |
| 橘 標籤 | `#dd9861` | 7.94:1 | 4.5 |
| 橘 說明 | `#ee8f44` | 7.86:1 | 4.5 |

送出鈕是白底：藍塊 `#0f3661` 12.21:1、橘塊 `#8a3d00` 7.64:1。

> 量測陷阱：白字疊在深底上時，**最亮的像素就是字本身**。取「背景色」時
> 白字要取暗端、深色字要取亮端，取錯會得出 1.04:1 這種假數字。

### 高度跟著內容走

不設 `min-height`。一般訪客只有四個欄位，固定下限會讓它展開時底下空一大片。

> 踩過的坑：收合側原本只用 `visibility: hidden`，但**那會保留版面空間**——
> 七個欄位被擠進 5.5rem 的窄帶後高度暴增，整列反而比展開前還高
> （實測 836 → 1422）。收合側的 `.body` 要一併用
> `grid-template-rows: 0fr` 收掉高度，改完是 602。

送出鈕 `justify-self: center`。

### 滑動

520ms → **720ms**，曲線從 `cubic-bezier(0.32,0.72,0,1)` 換成
`cubic-bezier(0.65,0,0.35,1)`。原本的收尾太急，「滑到一半卡住」的感覺
是從那裡來的；新曲線兩端都平緩。手機的高度展開同步調成 560ms。

- **桌機（900 以上）**：左右並排各半，點擊後選中側撐到 `100% - 5.5rem`、
  另一側收成 `5.5rem` 的窄帶，標籤轉直式。動畫用 `flex-grow` / `flex-basis`。
- **手機（900 以下）**：上下堆疊，「蓋住另一邊」不成立，改成兩塊預設都收起、
  點開才展開（`grid-template-rows: 0fr → 1fr`）。不這樣做的話整頁會是兩份
  完整表單。

收合側的內容用 **`visibility: hidden`** 隱藏，不是只降 opacity——
隱藏的元素本來就不可聚焦，比用 JS 逐一改 `tabindex` 可靠，也不必在 JS 裡
再判斷一次斷點。切換延遲到動畫結束，才不會一點下去內容就消失。

| 區塊 | 欄位 |
| ---- | ---- |
| 一般訪客 | 姓名、電話、信箱、諮詢內容 |
| KYC | 公司行號、統一編號、姓名、職稱、信箱、電話、公司電話（選填） |

KYC 七個欄位在桌機展開時排成兩欄，單欄會拉得太長。

### 統一編號有做檢查碼驗證

逐位乘上權重 `[1,2,1,2,1,2,4,1]`，把每個乘積的十位與個位相加，
總和能被 5 整除即為有效；第 7 位是 7 時 `+1` 也算通過。

做這個不是為了嚴謹好看——統編打錯一碼表單照樣送得出去，
但收到的資料是廢的，而且**沒有後端可以事後補救**。
已用真實統編驗證（04595257、23638777 通過；12345678 擋下）。

## ⚠️ 送出目的地尚未接

GitHub Pages 沒有後端，表單資料沒有地方可以送。CLAUDE.md 要求實作前先確認
要走哪一種，所以目前 `handleSubmit` 只擋下事件、**不送任何資料出去**。

兩個選項各有代價：

- **`mailto:`** — 無第三方、無相依套件，資料只經過訪客自己的郵件軟體。
  但體驗差（會跳出郵件軟體）、無法驗證送出成功，且收件信箱會暴露給爬蟲。
- **Formspree 之類的第三方** — 體驗好、有送出確認。但**資料會經過並儲存在
  第三方**。KYC 收的是統編、姓名、職稱、電話這類身分資料，
  這需要隱私權政策配合，是商業決定不是技術決定。
